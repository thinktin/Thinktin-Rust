# 多语言（WBS 1.6，服务端部分）

一个全球产品，先支持**简体中文**（`zh-CN`，默认）和**英文**（`en`）。App 界面的文案由客户端自己翻译；
这里说的是服务端写给用户看的文字怎么按用户的语言输出。

## 1. 用户的语言

- 存在 `users.locale`（`zh-CN` / `en`），接口里是 `User.locale`。
- **新用户**：登录接口按请求头 `Accept-Language`（设备的系统语言，按 q 值从高到低取第一个支持的）定；
  认不出（比如日文）就用中文。
- **老用户再登录不改**：之后只由用户自己改。
- **改语言**：`PATCH /v1/me`，`{"locale": "en"}`。也接受系统的语言标签（`zh-Hans-CN`、`en_US`、`zh-TW` 都认，
  繁体先归到中文）；不支持的返回 422 `invalid`。客户端核心：`set_locale(locale)`，用户在 App 里换语言时调一次。
- `PATCH /v1/me` 现在是真正的部分更新：没带的字段不改，`"display_name": null` 才清空名字。

## 2. 按语言输出的

| 文字 | 位置 |
|---|---|
| 推送和收件箱：账号冻结 / 恢复、全部停止、审批提醒、审批超时跳过、计划待确认、请填账号密码、任务完成、流水线完成、任务失败 | `orchestrator::texts` |
| 运行等 key 时的状态说明（也是推送正文） | `orchestrator::waits::KeyProblem::describe` |
| 推送里 agent 生成内容的显式标识（`【AI 生成】` / `[AI-generated]`） | `notify::PushMessage::display_body`，按推送里的 `locale` |
| IM 群消息（10.5）：标题前的品牌名、审批只能在 App 里做的提示、测试消息、渠道失效停用的通知；飞书富文本的语言（`zh_cn` / `en_us`） | `orchestrator::texts`（`im_*`）、`notify::im` |
| 内容过滤命中时系统通知里的中性提示 | `notify::filter::blocked_body` |
| 下载的文本产出物末尾的显式标识 | `proto::labels::text_footer_in` |
| 平台交给 agent 的说明：续跑说明和续跑简报（7.12）、委派的子任务说明和交还的结果（8.7）、流水线的交接说明（8.5） | `orchestrator::texts` |

出箱里的推送消息带收件人的语言（`PushMessage.locale`），写出箱时从库里取，调用方忘了也不会错。

给 agent 的说明也按用户的语言写：它们会出现在用户看得到的对话里，agent 也会跟着用这种语言回复。
平台工具的说明和返回值（`schedule_*`、`delegate`、`artifact_*`）是给 agent 的接口文档，保持英文。

## 3. 不翻译的

- **agent 写的内容**：运行摘要、工具调用的标题、计划标题、用途说明，原样转发。
- **接口错误**：`code` 是给客户端的契约，客户端按错误码显示自己语言的文案；`message` 是给开发者看的英文说明。
- **失败原因**：运行的失败原因是平台记下的诊断信息（英文），推送里前面加上按语言的“任务失败：” / “Task failed:”。
  以后要完全本地化，改成原因码 + 客户端文案。
- 品牌名 ThinkTin。

## 4. 加一种语言

1. `proto::domain::Locale` 加一个取值，`Locale::from_tag` 认出它的语言标签；
2. 迁移里放宽 `users.locale` 的 `CHECK`；
3. `orchestrator::texts`、`KeyProblem::describe`、`notify::filter::blocked_body`、`proto::labels` 里补上这种语言
   （`match` 没覆盖到会编译不过）；
4. 显式标识的文字上线前请法务确认（《人工智能生成合成内容标识办法》）。
