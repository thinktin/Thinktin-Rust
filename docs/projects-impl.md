# 项目与跨用户协作的实现顺序（8.13–8.19）

此稿承接[已确定的产品规则](projects.md)和同一用户 agent 交流的 [PR #18](https://github.com/thinktin/Thinktin-Rust/pull/18)。它覆盖邀请、授权、数据边界与退出后的体验，供分阶段开发与评审。跨账号功能尚未上线。

## 产品评审

用四个任务比较原先的 A、B、C 三案：旧版 App 领养团队、甲邀请乙的两个 agent、乙中途撤回一个 agent、甲删除项目。安全和实现评审首选 A；其数据库侧隔离也最贴近用户“只共享项目工作”的预期。采用 A 的独立成员角色，结合 B 的调度权限与事件裁剪、C 的删除流程。下列验收是取舍依据。[A 案](progress/drafts/projects-design-A.md) · [B 案](progress/drafts/projects-design-B.md) · [C 案](progress/drafts/projects-design-C.md) · [已有评审](progress/drafts/projects-judgments.json)

沿用首版边界：每项目最多 10 位用户、30 个 agent；主人设定的预算内自动执行，通知主人且可随时停止；项目暂不转让，模板仅自己使用。并发加入时在同一项目锁内核算人数和实例数。

- **旧版领养。** 已发布的 `/v1/teams*` 和 Team FFI 继续可用。一次领养应同时建好全部实例及单人项目，失败时全部回滚。新增单人项目的受限写入口须复用现有 tenant 事务；跨用户写只能由服务端执行。迁移过渡期确保两种客户端指向同一项目 ID，避免重复领养、双份编辑和孤儿实例。
- **受邀加入。** 主人先看到目标、创建者和会共享的数据，再逐个选择实例，为自己承担的日/总预算设限，并确认内容会发给这些实例的模型供应商。显示专属与混用的区别；试点跨用户项目只接入可以做到进程和文件隔离的实例。向不存在、已注册或屏蔽邀请人的号码返回一致结果。邀请令牌短期、单次、仅存哈希，接受与过期/撤回在同事务中竞争。重复接受返回已有结果。
- **执行和求助。** 创建者和其指定负责人可派项目任务；成员主人可停止或撤回自己的实例。执行费用归实例主人，审批仅发给主人，项目里只显示“等待主人处理”。看板、提问、委派和产出物都带项目范围。成员不会从失败原因、花费、时间线或工具卡片读到他人的私人活动。
- **退出和删除。** 离开立即断开项目流，已加载的项目页面进入“已退出”并清除可撤回的本地缓存。其他成员继续使用项目产出物，作者显示“已退出的成员”。项目删除后即刻不可读，清理可重试。用户本来就能保存屏幕或导出获准访问的数据，撤权不承诺擦除外部副本。

## 数据、身份与现有接口

1. 增加 projects、members、agents、invites 和项目专用密钥索引。所有共享对象显式存 `project_id`；运行仍存真实 `user_id`。父子运行、授权和产出物用类型化 scope（私人/项目）及复合外键限制在同一域。保留审批与事件原来的 `(run_id,user_id)` 约束，再加 scope 一致性约束；ID 碰撞也不能跨私人/项目类型。项目归属由服务端或触发器从关联运行派生，更新时不可改。预算、模型 key 和收费明细始终归各主人。
2. 普通 App/私人任务继续走 tenant 事务，私人工具只读取私人行。独立 `thinktin_member` 角色默认无权访问业务表；`ProjectTx` 只读、只暴露窄查询。数据库同时检查当前用户、存活成员关系和项目状态，手动设置另一个项目 ID 也读不到。tenant 查看自己实例历史时亦受成员状态约束；退出后不能从旧接口旁路读取。对 SECURITY DEFINER 函数固定搜索路径、限定输入、撤销 PUBLIC EXECUTE；属主为受限 NOLOGIN、NOBYPASSRLS 角色。测试必须包含生产同款非超级迁移角色和 FORCE RLS。
3. 跨账号派单、创建项目运行和签发子授权仅允许 worker。worker 从经过锁定和验证的成员关系得到不可自行构造的 `ProjectActor`，核验创建者/负责人、目标实例的派驻、项目状态及双方授权交集。同一事务内按项目、成员、实例固定顺序锁定；授权与项目两侧任一祖先撤销均失效。DB 拒绝 tenant 伪造项目运行、项目授权或跨成员子运行，复合外键本身不能代替权限检查。私人授权查找明确排除项目授权。
4. 预算按（项目，主人）独立预留，重试沿用同一运行幂等键；模型网关复核当前授权与令牌代数。模型密钥、审批原文、费用、保险箱和电脑默认仅主人可见。例外需主人针对具体项目授权，保险箱按条目 ID，禁止项目 agent 发起私人凭据收集表单。撤回成员或实例时停领、取消在途工作、递增令牌代数，同时撤销打开的连接。
5. 每个（实例，项目）有独立会话、HOME、cwd、工具配置与归档密钥。私有目录与项目目录平级，同一可执行任意 shell 的 OS 身份不能用路径命名实现隔离。混用实例必须提供分离的挂载/运行环境，验证其无法遍历兄弟目录、读取旧的模型记忆或恢复其他 scope 的快照后才开放。项目产出物用项目 DEK；私人工作区归档不得夹带可被个人 DEK 解出的项目明文。
6. 邀请和退出回执写入收件人私有 inbox，只带操作回执和必要的公开上下文。项目通知实时复核成员资格；普通成员看到按事件种类白名单生成的 DTO（例如工具 ID、类别、状态），不暴露原始参数/输出、思考、私人审批或实例序号。项目读流使用独立的 project_seq。用事务 outbox 把可公开事件交给独立排序器，以稳定事件 ID 去重，游标与投影在同一事务落库。建立项目游标索引，普通业务角色无权写 feed 或更新序号。避免每次写模型字块都跨实例抢同一行锁。
7. 删除项目先短事务置为不可读、撤权、使密钥不可解；被调用方每次解密与发事件都检查状态。后台按有界批次清理内容、缓存、归档和对象版本；失败后从检查点恢复。账号注销先取消自己的运行，保留其他主人仍需的记录；跨主人的子运行保留父关联（8.17：用户行从不真删，注销只删私人运行，项目清理从新到旧删项目运行，所以级联从不跨主人），保留 scope 和所有权外键，避免级联误删；已退出成员的显示名匿名化。仅保留已说明的最小审计字段。

## 迁移与放量

- **8.13 · 单人兼容。** 从当时目标分支的最后迁移连续编号；先增加可空字段和新结构，再回填。迁移事务在必要表临时解除 FORCE、按行数及成员/实例外键核对、恢复 FORCE。并行建测试库要处理集群级角色的创建竞争。大表索引独立迁移；并发建索引时每个非事务文件只放一条命令。通过旧客户端读写及领养的失败回滚测试后才切读路径。
- **8.14–8.16 · 授权与隔离。** 先上线邀请生命周期与默认拒绝的读模型。所有版本的 worker 须在 claim、重试和 takeover 都排除自己无法隔离的项目运行；确认旧副本已退出后才允许写入可执行项目任务。单独验证旧客户端不会把项目事件保存到私人缓存，再启用多成员只读。
- **8.17–8.19 · 派单、预算与通知。** 开启专属实例的项目任务、审批、项目 feed；以两位不同主人实测预算与撤权。随后独立评审非专属实例和高风险工具授权。回退按相反顺序关功能，先停新建与领取、处理在途授权，保留已回填的单人团队兼容读取。

## 8.14 做了什么（2026-11-05）

按 `progress/drafts/projects-8.14-plan.md`（代码地图、草稿、评审在同一目录），分 13 步提交。

- **总开关** `[api] cross_user_projects`，默认关（15.7 安全评审之前）：关着时发邀请、预览、接受、看发给我的邀请都 404；
  单人项目、`/v1/projects` 的列表和详情照常。
- **跨用户的写都在 worker 事务里**，动作人只来自登录态；store 里的 `ProjectActor` 在同一个事务里按固定顺序加锁、核对成员关系
  （用户行 → 项目锁 → 自己的成员行 → 窄的咨询锁 → 邀请行 → 别人的成员行 → 项目 agent 行 → 运行 → 实例），网关和编排层
  造不出它。不是成员的一律 404（不说项目在不在），成员调只有创建者能用的接口 403。租户改单人项目（旧的团队接口）也先拿项目锁，
  免得和加入同时进行时 agent 数超过上限。
- **邀请**（迁移 0047）：只有创建者邀请，要先设昵称。手机号邀请只在 App 里通知、不发短信，7 天有效；链接邀请 72 小时、用一次，
  库里只有令牌的 SHA-256，令牌只在请求正文里（`tpi1_…`，App 链接 `thinktin://join/<令牌>`）。按手机号邀请不管号码注册没有、
  对方拉黑没有、是不是已经在项目里，回的都是 201 和同样的内容；`invitee_id` 只表示“通知送达了谁”，从不给邀请人看。
  上限：每个邀请人 24 小时 20 个（429，`[api.limits] invites_per_day`）、每个项目 20 个待处理的（409 `project_invite_limit`）、
  每个号码 24 小时 5 条通知（超了的照样有效，只是不推送，`invites_per_phone_per_day`）；两个 24 小时的数按发送记录算（删项目
  不清零）。结束 30 天的邀请删掉（明文手机号不久留）。
- **拉黑**：被拉黑的人发来的手机号邀请照样“发出”，但标不送达（`suppressed_at`），对方看不到、接受不了，邀请人那边到期变“已过期”；
  “拒绝并拉黑”也一样（不标“已拒绝”）。取消拉黑不恢复。拉黑和发邀请同时进行时按咨询锁排队，不会漏下一条送达的。
- **加入**：选 1–30 个自己的 agent、设每天和总的 token 预算、确认加入说明（`consent: true`，库里记确认时间，审计里记实例、
  模型厂商、预算和说明的版本）；一个项目最多 10 个人、30 个 agent（实例删了的不算），都在项目锁里数（409 `project_member_limit` /
  `project_agent_limit`，邀请不作废）。退出、被移出以后再加入，原来的成员行、agent 行原地恢复。
- **增派、撤回、退出、移出**：成员能加、撤自己的 agent，创建者能撤任何人的；创建者不能退出（只能删项目，共享过的 8.15 起软删除）；
  移出是创建者的事。撤回、退出、移出时先停掉这个项目里的运行（令牌代数加一）、吊销项目里的授权，同一个实例的私人运行和授权不动
  （8.14 还没有项目运行，8.17 起才有）。删实例以后由 worker 把它从共享项目里撤下，后台兜底（项目锁被占着时跳过、下一轮再说）。
- **读**：`GET /v1/projects`、`/v1/projects/{id}` 是 worker 读、同一句 SQL 里核对成员关系（8.15 换成成员事务，返回的结构不变）。
  邀请预览给不是成员的人看项目名、目标、创建者（拉黑要用他的 id）、其他成员的昵称、身份和 agent 数（没有用户 id），以及加入后
  哪些项目里的人看得到、哪些还是自己的（固定的键，App 翻译）。
- **回执**：`info` 加子类型 `project_invite`、`project_joined`、`project_left`、`project_removed`、`project_agent_left`、
  `project_agent_removed`（[推送](push.md)）。发给可能不认识的人的邀请通知不带邀请人能写的字（名字、项目名），免得被拿来在锁屏上
  发广告。审计每个相关的人一条，不记手机号，给一个人的那条不记另一个人的实例 id 和模型厂商。
- **client-core**：`projects()`、`project()`、`create_project`、`create_project_invite_link`、`invite_to_project_by_phone`、
  `resolve_project_invite_link`、`accept_project_invite(_link)`、`decline_project_invite`、`withdraw_project_agent`、
  `leave_project`、`remove_project_member`、`set_project_budget`、`block_user` 等；`project_invite_token()` 本地核对链接格式。
  安卓绑定已重新生成；App 的界面在 12.25、13.18。
- **没做（留给后面）**：`/v1/project-templates*`（`/v1/team-templates*` 已经读写项目模板，8.15 加别名）；删、归档共享项目（8.15）；
  跨用户换负责人（8.17）；加入时顺便领养新实例（现在是两步：先领养、再接受）。
- **对抗评审**（`progress/drafts/projects-8.14-review.md`，4 个方面、每个方面一个反驳者）：21 条成立 19 条（去重后 15 条），都修了：

    改成数迁移 0048 的发送记录 `project_invite_sends`（只有 worker 读写，不跟着项目删，两天后后台删掉；注销时删发给他号码的，
    他发的只去掉是谁发的，不然注销、重新注册就能把对方号码的上限清零）。删单人项目改由 worker 在一个事务里做：核对身份

  - 被移出的人能拿着自己还是成员时收到的手机号邀请自己回来：退出、移出时把这个项目里发给他号码的待处理邀请标不送达（和拉黑

  过期、提问超时、父运行结束、流水线停下、归档、撤下、冻结、关开关），提醒都算已读。“全部停止”和冻结先锁用户行（`FOR NO KEY
  UPDATE`），项目里加锁拿 `FOR SHARE`：和派单互相等，又不挡外键检查（不会和锁着运行再写收件箱的事务互相等死）。等确认的提问、
  委派，回复和普通排队的一样（谁问的都一样：项目运行里 agent 说的话每个成员都看得到），只有给主人的提醒说要确认。
- **项目看板**（迁移 0062）：单独一张表，成员和成员的 botin 写，成员读，租户一点权限都没有；作者、创建者能归档、删；每人每天手动
  50 条，没归档的最多 200 条；和项目运行一样存（按成员关系挡、删项目时一起删），不单独用项目密钥加密（用户的决定 2）。
- **项目流水线**（迁移 0065）：创建者开始，1–20 步，每一步在项目里任何一个专属 botin 上；根运行挂在创建者自己的专属 botin 上（不带
  授权，别人“全部停止”、撤下碰不到它；查队友、查进度、提问不把根运行算成它在忙）；驱动每个根运行一个事务；步骤也受“每个 botin
  最多排 10 个”的限制（排满了这一步下一轮再开，流水线不失败；开始时那个 botin 已经排满了回 `agent_busy`）；交接说明按这一步
  主人的语言，上游的结果和产出物放在边界里、注明是别的 botin 写的；上游产出物里 agent 会自己读进去当说明的文件名（`CLAUDE.md`、
  `AGENTS.md` 这类）改成 `<名字>.upstream.txt` 再放进工作区；一步没成功时根运行只记“step X failed”，不抄对方的失败原因；
  没写目标的，读回来目标是空的。
- **编排层**：项目里的运行能用 12 个项目工具（委派只给项目的负责人，私人看团队、项目看项目）；查队友只看项目里专属的 botin，查进度
  只给成员能看的；看板读写项目看板，不抹值（抹了反而让成员从抹掉的位置猜出主人的密码）；库里存原文，启动时按当时的名字加平台
  说明（谁派的、谁问的、是谁的 botin），每次尝试都加；交还结果时不给失败原因、注明是别的 agent 写的；别的成员的 botin 发布的产出物
  读的时候带边界；别人派的活做完、失败的推送只写平台的话；项目运行不捎带排着的消息；执行器定时清理没人要的子任务。
- **出口代理**（迁移 0064）：问用户“能不能访问这个网站”时带上验过的令牌代数，旧沙箱的不登记（8.16 复核留下的那一条）。
- **接口**：`POST /v1/projects/{id}/runs`、`…/runs/{run}/cancel`、`…/runs/{run}/confirm`、`PUT …/lead`、`GET/PUT
  …/agents/{实例}/limits`、`GET/POST …/board`、`…/board/{条目}/archive|unarchive`、`DELETE …/board/{条目}`、`POST …/pipelines`、
  `GET …/pipelines/{根运行}`、`DELETE …/artifacts/{id}`；`ProjectDetail.can_dispatch`；任务、看板、流水线里有自己保险箱里的值 422。
  给别人的 botin 派任务、开始流水线时，对方的预算用完了和用不了（账号冻结）都回 `agent_unavailable`（不让创建者分辨别人的预算和
  账号状态），自己的 botin 才分开报 `budget_reached`。看板每天 50 条满了，`Retry-After` 是到最早那条满 24 小时还要等多久。

  又提问时也注明子任务结果是别的 agent 写的）。

  检查，前面已经挡了）。
- **收尾的对抗评审**（`progress/drafts/projects-8.17-final-review.md`，原文在 `-raw.md`；4 个方面、每条一个反驳者）：27 条成立

  - 中：流水线的步骤不受“每个 botin 最多排 10 个”管，每一步拿主人剩下的全部预算，开很多条能花到限额的很多倍。
  - 隐私（都是低）：创建者从 409 的代码分得出别人的预算用完了还是账号冻结了；提问、委派的回复告诉别的主人的 agent“对方主人

    目标还剩的，执行器却把树里这个主人已经用掉的也算进来，负责人先花得多了，子运行一开始就超（中；流水线后面的步骤本来就有这个
    问题，一起修了）；冻结改成 `FOR UPDATE` 以后会和“锁着运行再写收件箱”的事务互相等死（“全部停止”从 C6 起就有），改成

## 合并实现前的测试

用甲、乙、未入组的丙和两个不同项目在真实 PostgreSQL 运行，按 tenant、member、worker 以及生产规格迁移账号分别断言：

1. 验证产品四条主路径，加入重试、超时接受、撤邀请并发与最后一个负责人退出的结果唯一。旧版 API/FFI 在新库仍可原子领养和读写单人团队。
2. 伪造项目 GUC、猜 ID、跨 scope 父子运行、伪造授权和直接写 feed 一律拒绝。甲乙分别看不到对方的私有工具输出、花费及审批；丙没有成员目录或存在性侧信道。
3. 使用屏障并发撤权与派单、预留最后预算、重新连事件流。提交撤权后即便旧票据、游标或缓存仍在，也不能启动下一次外部调用；旧客户端和 worker 不能借私人通道绕过。
4. 删除甲账号后乙的子运行、审批和归属仍在；模拟删除项目各阶段崩溃并重启，读取先失效且垃圾最终清掉。归档恢复、下载和离线缓存使用同一范围检查。
5. 多实例高频事件下，客户端按自己的项目游标重播无缺失、无串流；测索引计划、积压、并发锁和清理批次。通过安全评审及旧版回滚演练后再面向多人开放。
