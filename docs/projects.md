# 项目与跨用户协作（设计）

跨用户权限、迁移兼容、产品评审和验收顺序见[实现方案](projects-impl.md)。

> 状态：设计，2026-10-27 写，**还没开工**。工作包见 [WBS](wbs.md) 1.7、8.13–8.19、12.25、13.18、15.7、16.6、17.8。
> 依据：用户 2026-10-27 的决定（第 1 节）；同一用户 agent 之间的交流见[架构方案](architecture-v3.md) 4.11。

## 1. 用户定下来的

- **团队就是项目组**：用户单独建一个项目，把 agent 安排进来当成员，这些成员就是项目的团队。
- **可以跨用户**：别的用户也能把自己的 agent 派进同一个项目。
- **派几个由用户自己定**：每个用户可以派一个，也可以派多个自己的 agent。
- **谁指挥**：项目创建者，加上他指定的负责人 agent，给项目派任务、编排流水线、委派给成员 agent。其他成员的主人只能管自己的 agent（停止、撤回、退出）。
- **电脑和保险箱**：项目里的运行默认用不了电脑控制和保险箱，由 agent 的主人单独授权。
- **顺序**：先做同一用户 agent 之间的交流（4.11，8.9–8.12），项目组放在它后面。

## 2. 两层交流

| 层 | 谁和谁 | 能做什么 | 看得到什么 |
|---|---|---|---|
| 同一用户 | 一个用户领养的全部 agent | 认识队友、查进度、共享看板、提问（4.11） | 彼此的全部工作 |
| 项目 | 项目里的成员 agent，可以来自不同用户 | 同上，再加项目看板、委派、流水线 | **只限这个项目里的工作**：别人的私人任务、私人对话一律看不到 |

同一个 agent 可以同时在两层里：它和主人的其他 agent 照常交流；进了项目，在项目里只以“项目成员”的身份出现。

## 3. 概念和数据

| 对象 | 内容 |
|---|---|
| 项目 `Project` | 名称、目标说明、创建者、状态（进行中 / 已归档 / 已删除）、项目密钥（KMS 包裹的 DEK） |
| 项目成员（用户）`ProjectMember` | 用户、角色（创建者 / 成员）、加入时间、这个用户给自己 agent 定的项目预算 |
| 项目 agent `ProjectAgent` | 实例、它的主人、是否负责人、是否专属于本项目、主人授权的额外能力（电脑、保险箱，默认都关） |
| 邀请 `ProjectInvite` | 邀请人、被邀请人（手机号或邀请链接）、状态、过期时间 |
| 项目运行 | 普通运行加上 `project_id`：在成员 agent 的沙箱里执行、用 agent 主人的 key，运行记录对项目成员可见 |
| 项目看板、项目产出物 | 归项目所有，用项目密钥加密，成员都能读 |

**和现有“团队”的关系**：现在的团队（同一用户的几个实例，带负责人，可以存成模板）变成“只有创建者一个用户的项目”。现在还没有线上数据，迁移只在代码和客户端：团队页改成项目页，团队模板改成项目模板（按 agent 种类描述成员，领养时建实例），流水线和委派的范围从“团队”改成“项目”。

## 4. 生命周期

1. **建项目**：用户起名、写目标，从自己的 agent 里选一个或多个加进来，可以指定一个负责人 agent。
2. **邀请**：创建者用手机号或邀请链接邀请别的用户；每天的邀请数有上限，被邀请人可以拉黑邀请人。
3. **加入**：被邀请人看到项目名、目标、创建者、现有成员，然后：
   - 选派自己的一个或多个 agent（可以当场新领养一个专门给这个项目的）；
   - 给自己派出的 agent 设项目预算（每天 / 总计的 token 上限）；
   - 确认“项目内容会发给你的 agent 用的模型厂商”。
4. **调整**：成员随时可以增派、撤回自己的 agent；创建者可以移出任何成员或 agent、更换负责人。
5. **退出**：成员退出时，他的 agent 停掉项目里正在做的事、离开项目；他之前在项目里留下的看板条目和产出物留在项目里（作者显示“已退出的成员”）。
6. **归档、删除**：创建者可以归档（只读）或删除。删除时销毁项目密钥，项目看板、产出物、项目运行的内容都读不出来了（和账号注销的“删密钥即销毁”同一个做法）。

## 5. 数据边界

现在整个系统按用户隔离：每张表都有 `user_id`，数据库行级安全只让一个用户看到自己的行；产出物用每个用户自己的密钥加密。项目要在这上面开一个**受控的口子**，原则是“项目的东西归项目，个人的东西归个人”：

- **项目自己的表**（项目、成员、项目 agent、邀请、项目看板、项目产出物索引）：行级安全按“是不是这个项目的成员”放行，不再按 `user_id`。
- **项目运行**：运行行照旧属于 agent 的主人（花谁的 key、记谁的用量、审批找谁都清楚）；另加一条规则：带 `project_id` 的运行和它的事件，项目成员也能读。没带 `project_id` 的运行永远只有主人能看。
- **项目产出物**：用项目密钥加密，成员都能解；agent 在项目运行里发布的产出物进项目空间，私人运行发布的进主人自己的空间，两边互不可见。
- **查进度、提问跨用户时**：`agent_status` 只汇总对方在本项目里的运行；`ask` 只送进对方的项目会话（第 6 节），永远不碰私人会话。
- **私人资产不进项目**：保险箱条目、电脑、模型 key、私人产出物、私人看板，项目里都看不到；电脑和保险箱要主人对这个项目单独授权（第 7 节）。

这部分改动碰到租户隔离，要单独做安全评审和越权测试（15.7、17.8）。

## 6. 会话和工作区隔离

agent 有记忆（Claude 的项目记忆、Hermes 的技能和记忆等，存在实例的状态目录里）。一个实例既做主人的私事又做项目，私人信息可能被带进项目，项目内容也可能被带回私人对话。用户决定派哪些 agent，平台这样配合：

- **每个（实例，项目）一个独立会话和独立工作区目录**：项目里的对话不和主人的私人对话混在一起，文件也分开放。
- **专属实例**：加入时可以当场领养一个新实例专门给这个项目，或者把已有实例标成“专属于本项目”。专属实例不接私人任务，记忆里只有项目的东西。
- **非专属实例的提示**：跨用户项目里派一个非专属的实例时，App 明确提示“这个 agent 的记忆里有你的私人内容，可能被带进项目”，用户确认后照样可以派。同一用户自己的项目不提示。

## 7. 指挥、费用、审批和权限

| 事项 | 规则 |
|---|---|
| 谁能派任务 | 项目创建者在 App 里给项目下任务、建项目计划和流水线；负责人 agent 用 `delegate` 委派给任何成员 agent（不分主人） |
| 成员主人的控制 | 随时停止、撤回自己的 agent，改预算，改授权；看得到自己 agent 在项目里的全部运行 |
| 费用 | 每个 agent 用**它主人**的模型 key，token 花主人的钱；到了主人设的项目预算就停在“等额度”，不会花超。运行树的共享预算（8.6）在项目里按 agent 的主人分开记 |
| 审批 | agent 要做超出预授权的操作，审批推给**它的主人**，不是项目创建者 |
| 预授权范围 | 项目运行的范围 = 项目给的范围 ∩ 主人给这个 agent 的范围，只会更窄 |
| 电脑、保险箱 | 默认不能用；主人可以对这个项目单独打开（比如允许它在项目里用某个保险箱条目），随时可以关 |
| 打断 | 项目创建者可以打断项目里任何 agent 的项目运行；agent 的主人可以打断自己的 agent；负责人 agent 可以打断替它干活的成员（4.11） |

## 8. 通知

推给相关的人，不是推给全部成员：

- 邀请、加入、退出、被移出：推给当事人和创建者。
- 项目任务完成、失败：推给创建者，以及出了力的 agent 的主人。
- 审批：只推给 agent 的主人。
- 项目看板有人 @ 某个用户：推给他。
- 事件流按项目过滤：在项目页只看项目里的事。

## 9. 安全和滥用

- **跨用户的提示注入**：别人的 agent 写的看板、产出物、回答，都按不可信输入交给 agent（和网页内容一样，不当指令）。项目里默认没有电脑和保险箱，高危操作照样要主人审批，所以被诱导也做不了大事。
- **越权**：行级安全和接口两层都按项目成员关系检查；退出、被移出的瞬间就看不到了。15.7 做专门的越权测试。
- **邀请滥用**：每天邀请数上限、被邀请人可以拉黑、邀请链接有过期时间和次数上限。
- **资源滥用**：项目运行照样受每个用户的沙箱时长、并发上限约束（算在 agent 主人头上）。

## 10. 合规

- 隐私政策加“和其他用户协作”一节：项目内容会被其他成员看到，会发给各成员 agent 用的模型厂商。
- 加入项目时单独确认这一点。
- 账号注销：他的 agent 离开所有项目，他建的项目一起删除（销毁项目密钥）；他在别人项目里留下的内容保留，作者显示为“已注销的用户”，内容里如果有个人信息，按注销流程（WBS 16.4）处理，细则在 16.6 定。

## 11. 待定

- 跨用户委派要不要成员主人逐个确认？默认：在主人设的预算内自动执行，主人收到通知、可以随时停。
- 一个项目最多多少个用户、多少个 agent？默认：10 个用户、30 个 agent。
- 项目能不能转让给别的成员？默认：首版不支持。
- 项目模板要不要能分享给别的用户？默认：首版不支持。
