# 威胁建模（WBS 15.1）

> 按架构方案第 3.6、5.6、6 节逐项建模，含多 agent 协同与运行授权。每条威胁写明已经落地的对策（代码位置或测试）和剩余风险。
> 代码或架构变了要同步更新；上线前由安全负责人复核，并作为第三方渗透测试（15.6）的输入。

## 1. 要保护的东西

| 资产 | 为什么重要 |
|---|---|
| 用户的厂商 LLM key | 泄露即被盗刷，用户直接损失钱 |
| 对话、提示词、产出物 | 用户的私人和工作内容 |
| 登录会话、刷新令牌 | 拿到即可冒充用户 |
| 运行授权、沙箱令牌 | 拿到即可用用户的 key 调模型 |
| 计划（定时任务） | 被篡改后会在没人看着时反复运行、花用户的钱 |
| 推送通道、手机号 | 骚扰、隐私 |
| KMS 主密钥、令牌签名私钥 | 平台级失守 |

## 2. 信任边界

```
手机 App ──(1)──> 接入网关 / 控制面 ──(2)──> Postgres、对象存储、KMS
                        │
                        (3) 沙箱令牌、任务
                        ▼
               沙箱：agent-shim + 开源 agent（不可信）──(4)──> 模型网关 ──(5)──> 厂商
                        │                                     
                        (6) 平台工具（MCP）回到控制面
控制面 ──(7)──> 推送服务（APNs、极光 / 厂商通道）
```

不可信：开源 agent 和它读到的一切内容（网页、文件、邮件、上游步骤的产出物）、用户填的自定义 base URL、客户端发来的任何参数。

## 3. 威胁与对策

### 3.1 沙箱里的 agent（边界 3、4、6）

| 威胁 | 场景 | 已落地的对策 | 剩余风险 / 待办 |
|---|---|---|---|
| 偷 key | 提示注入或恶意技能让 agent 读环境、读文件找 key | key 从不进沙箱，沙箱里只有短期沙箱令牌（环境变量，不落盘）；端到端测试扫描沙箱文件和日志（`crates/e2e`） | — |
| 沙箱令牌被带出去用 | agent 把令牌发到外面 | 令牌绑定实例、沙箱、运行授权和来源地址，短期有效，每次唤醒轮换；网关校验沙箱是否当前沙箱、授权是否有效（缓存最多 5 秒）（`crates/llm-gw/tests/pg.rs`） | 本地沙箱后端没有独立网络身份，开发环境不绑定来源地址；Cube 后端（6.2）要带上 |
| 用超出范围的模型 | 子运行的授权只给了某些别名 | 网关按授权的别名范围放行（`narrowed_grants_only_reach_their_aliases`） | — |
| 持久化恶意计划 | 注入让 agent 用 thinktin.schedule 建一个每天跑的计划 | agent 新建、修改的计划先暂停，推送提醒，用户确认（恢复）才生效；计划授权不超过发起调用的运行；只能动自己实例的计划（`crates/orchestrator/tests/tools.rs`） | 用户可能不看就点确认；App 里要把计划内容展示清楚（12.6 / 13.6） |
| 烧钱 | agent 死循环调模型 | 运行预算（时长、步数、token，以网关计费为准）；网关按实例限速和熔断；按 key 的每日预算（多副本共享） | 预算检查在请求前、记账在响应后，并发请求可能略超 |
| 供应链 | 技能市场里的恶意技能、agent 自更新 | 加固基线：关技能 / 插件市场、禁自更新、关遥测、控制台只听回环（`docs/agent-hardening.md`，测试守住）；模板版本锁定、升级回滚由平台控制 | 出网白名单要在部署时配好（2.7）；模板构建流水线（6.8） |
| 打穿沙箱 | 内核漏洞逃逸 | 每个实例一个 microVM（Cube，硬件隔离） | 依赖 Cube 的安全评估（2.4） |
| 访问内网和元数据 | agent 访问云元数据拿临时凭证 | 出网网关禁止内网和元数据 | 部署配置（2.7） |

### 3.2 多 agent 协同（边界 3、6）

| 威胁 | 场景 | 已落地的对策 | 剩余风险 / 待办 |
|---|---|---|---|
| 上游产出物注入下游 | 上游 agent 读了恶意网页，写进产出物，下游 agent 照做 | 产出物以文件形式放进下游工作区的 `handoff/`，交接说明写明来源；下游步骤的授权按步骤实例收窄；审批照常生效 | 本质上是提示注入，无法根除；高危操作（删除、发送、支付）要用户审批，不能预授权 |
| 越权到别人的实例 | 流水线步骤指向别人的实例 | 步骤的实例在库里核对归属（RLS + 显式检查），跨用户返回 404 | — |
| 一处失败到处乱跑 | 某一步失败后其他步骤继续烧钱 | 一步失败就停掉其余步骤，根运行失败并通知；用户可以一键停整棵运行树 | 委派（8.7，P2）上线前要加深度上限、循环检测、整树共享预算（8.6、8.8） |

### 3.3 客户端与接入网关（边界 1）

| 威胁 | 场景 | 已落地的对策 | 剩余风险 / 待办 |
|---|---|---|---|
| 越权访问别人的数据 | 改请求里的 id | 所有业务查询在用户的租户事务里，Postgres RLS 兜底；RLS 覆盖检查（新表忘开会失败）；36 个跨用户用例（`other_users_objects_are_invisible`） | — |
| 偷刷新令牌 | 手机被拿走、备份泄露 | 刷新令牌放系统安全存储；轮换，旧令牌重用即吊销整个会话；远程下线；事件流心跳时重新核对会话（4001） | 访问令牌 15 分钟内仍有效 |
| 短信轰炸、撞库 | 刷验证码 | 按手机号限频、每天上限、尝试次数上限；验证码只存 HMAC | 按 IP、设备的限流和注册风控（5.4，P2） |
| 产出物里的脚本 | agent 产出的 HTML 在浏览器里执行 | 下载按附件、`nosniff` | — |
| 审批被冒充 | 有人拿到会话后替用户批准高危操作 | 审批只能由登录的设备做；通知上只能直接拒绝 | 设备私钥签名（11.5、12.9、13.9，P2 / P3）上线前，会话失守即可批准 |
| 接口被打爆 | 大量请求 | 请求体大小限制、语句超时、连接池上限 | 接口限流（5.4） |

### 3.4 模型网关（边界 4、5）

| 威胁 | 场景 | 已落地的对策 | 剩余风险 / 待办 |
|---|---|---|---|
| SSRF | 用户自定义 base URL 指向内网 | 只允许 https；DNS 解析后拒绝内网、回环、链路本地、元数据；固定解析出的 IP 防重绑定；不跟随重定向；可走专用出口代理（`docs/llm-gateway.md`） | — |
| key 进日志 | 上游错误回显 key | 网关抹掉上游错误里的 key；日志只有打码令牌；端到端测试扫描 debug 级日志 | 进程内存里的残留（`docs/security-audit.md` 第 4 节） |
| 计费被绕过 | 流式响应不带用量 | 必要时替 agent 打开 `include_usage`；拿不到用量按保守估算记账；后台模式请求拒绝 | — |
| 注销后还能用 | 注销用户的令牌、key | 注销销毁 DEK、吊销授权，网关缓存过期后拒绝（`erased_accounts_cannot_use_their_keys`） | 缓存窗口（默认 5 秒） |

### 3.5 数据存储（边界 2）

| 威胁 | 场景 | 已落地的对策 | 剩余风险 / 待办 |
|---|---|---|---|
| 数据库泄露 | 备份外泄、拖库 | key、产出物内容按用户 DEK 加密；DEK 由 KMS 包裹；令牌、验证码只存哈希 | 对话、提示词、摘要在库里是明文（见待决问题 9） |
| 运维越权 | 内部人员直接查库 | 业务、后台、网关三个数据库角色权限分开；审计日志 | 需要数据库访问审批和审计（运维流程） |
| KMS 主密钥泄露 | 开发用的本地 KMS 主密钥在环境变量里 | 生产接云 KMS（2.6） | 2.6 未完成前不能上线 |
| 注销不彻底 | 注销后内容还在 | 注销删除内容、去标识化，逐表测试（`erasing_an_account_deletes_its_content`） | 对象存储里的密文由巡检清理（已无法解密） |

### 3.6 调度与执行（控制面内部）

| 威胁 | 场景 | 已落地的对策 | 剩余风险 / 待办 |
|---|---|---|---|
| 重复执行 | 多副本同时触发同一个计划、同一个运行 | 每次触发唯一约束；运行领取用 `FOR UPDATE SKIP LOCKED` 和租约，续租、接管、状态迁移都按租约持有者做 CAS | 副作用幂等（7.13，P2） |
| 退出登录后计划停跑 / 不该跑的还在跑 | 会话和授权混在一起 | 运行授权和登录会话分离；删除计划、实例、注销时吊销授权 | — |

### 3.7 推送（边界 7）

| 威胁 | 场景 | 已落地的对策 | 剩余风险 / 待办 |
|---|---|---|---|
| 内容泄露到第三方 | 推送正文经苹果、极光、厂商服务器 | 推送只放标题和一两句摘要，只带 id；内容过滤命中时换成中性提示 | 摘要本身来自 agent，仍可能含敏感信息；可以考虑只推“任务完成”不带摘要（产品决定） |
| 推给错的人 | 设备令牌失效后被别人复用 | 失效令牌（410、1011）立刻删除；退出登录、远程下线、注销清掉令牌 | — |

## 4. 待办汇总（按上线前必须完成排序）

1. 云 KMS（2.6）、出网白名单和元数据封禁（2.7）、Cube 后端带上沙箱网络身份绑定（6.2）。
2. 接口限流和注册风控（5.4）。
3. 审批的设备签名（11.5、12.9、13.9）：在此之前，高危操作的审批只靠登录会话。
4. 委派的护栏（8.6–8.8）上线前不开委派。
5. 对话内容是否按用户加密存储（待决问题 9）。
6. 第三方渗透测试（15.6）。
